# Filesystem publication / Fájlrendszeres közzététel

## English

Development builds first publish a verified ZIP using an exclusive hard link. If links are unsupported, they may use the native same-volume **no-replace rename**: macOS `renamex_np(RENAME_EXCL)`, Linux `renameat2(RENAME_NOREPLACE)`, or Windows' non-overwriting rename. A concurrent file, directory or link prevents replacement. No plain POSIX rename or streaming-copy fallback exists. If neither primitive works, publication fails and handled failures clean unpublished staging. This is not a claim of crash durability, hostile staging-path protection or verified FAT/exFAT/network-volume compatibility. Native CI tests exercise the actual exclusive primitive; non-link behaviour and races are simulated. Real removable-volume testing remains required.

Recovery preflights both final and temporary paths. POSIX limits use the destination filesystem's component/path capacities in encoded bytes; Windows uses a conservative 255 UTF-16 units per component and 259 for the entire path. It may reject paths on Windows installations that support longer paths. Choose a shorter parent, or explicitly use isolated portable-name recovery for native capsules. The latter does not automatically rewrite script/menu dependencies. Unusual filesystem allocation, quotas and names can still fail during writing; safe cleanup remains necessary.

New backup records carry original modification time and permission bits as informational metadata. Restore uses new-file defaults and current timestamps: it does not apply untrusted executable bits, ACLs, extended attributes, Finder metadata or ownership. ZIP member safety is separate from source metadata. A capsule is not a bit-for-bit filesystem image.

## Magyar

A fejlesztői verzió először kizárólagos hard linkkel teszi véglegessé az ellenőrzött ZIP-et. Ha a hivatkozások nem támogatottak, használhatja a natív, azonos kötetes **felülírás nélküli átnevezést**: macOS alatt `renamex_np(RENAME_EXCL)`, Linux alatt `renameat2(RENAME_NOREPLACE)`, Windows alatt felülírást tiltó átnevezést. Egy közben létrejött fájl, mappa vagy hivatkozás megakadályozza a cserét. Nincs hagyományos POSIX-átnevezésre vagy folyamatos másolásra visszaesés. Ha egyik művelet sem működik, a közzététel leáll, és a kezelt hibák eltakarítják a nem végleges előkészítést. Nem állítunk összeomlási tartósságot, ellenséges előkészítésiútvonal-védelmet vagy igazolt FAT/exFAT/hálózati kompatibilitást. A natív CI a tényleges kizárólagos műveletet teszteli; a hivatkozást nem támogató működést és a versenyhelyzeteket szimuláljuk. Valódi cserélhető köteten végzett teszt még szükséges.

A visszaállítás a végleges és ideiglenes útvonalakat is előre ellenőrzi. POSIX alatt a célfájlrendszer komponens- és útvonalhatárait kódolt bájtokban méri; Windows alatt konzervatívan komponensenként 255 UTF-16-egységgel, teljes útvonalra 259-cel számol. Ez hosszú útvonalakat támogató Windows-telepítésen is elutasíthat útvonalakat. Válassz rövidebb szülőmappát, vagy natív kapszulánál külön kérd az elkülönített hordozható névkinyerést. Utóbbi nem írja át automatikusan a script-/menüfüggőségeket. Szokatlan foglalási szabályok, kvóták és nevek továbbra is okozhatnak írási hibát; a biztonságos takarítás szükséges marad.

Az új mentési rekordok tájékoztató metaadatként tárolják az eredeti módosítási időt és jogosultságbiteket. A visszaállítás új fájlok alapértelmezéseit és aktuális időbélyegét használja: nem alkalmaz megbízhatatlan futtatási jogosultságot, ACL-t, kiterjesztett attribútumot, Finder-metaadatot vagy tulajdonjogot. A ZIP-bejegyzés biztonsága külön kérdés a forrásmetaadatoktól. A kapszula nem bitpontos fájlrendszerkép.
